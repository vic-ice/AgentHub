# 真实系统运行截图计划

## 1. 总体要求

论文截图必须由当前基准的真实前后端运行结果采集，不能使用设计稿或伪造数据。建议单独创建一个论文演示用户，只放不涉及隐私的测试书籍、会话和记忆；截图前统一浏览器缩放比例、窗口宽度和浅色/深色主题。

每张截图应包含足够的页面上下文，但不要截取浏览器地址栏中的敏感查询参数、开发者工具、终端日志或模型完整思考过程。正文中按“图 5-x 功能名称”编号，并在图后用 2～4 句解释输入、处理和结果。

## 4. 各截图的建议操作脚本

### S01 普通 Chat

建议测试问题：

> 我正在整理个人阅读计划，请说明怎样用本系统记录想读、在读和已读，并告诉我这些状态如何影响后续推荐。

应确认：回答直接面向用户；结构清晰；不暴露内部 JSON、提示词或“候选证据包”等工程术语。可同时打开“本轮执行”侧栏，证明问答与执行过程在同一会话中。

### S02 普通 Search

选择一个在 2026 年需要联网核验、但研究深度适中的公开问题。应确认：

- 一次回答中既有模型解释，也有实时来源补强；
- 来源链接可点击并与相邻结论对应；
- 某个 Provider 失败时，若其他 Provider 有有效命中，最终结果不应显示为整体失败；
- 不截图开发者工具中的 provider diagnostics。

### S03–S05 自然语言阅读事实闭环

推荐使用无隐私的演示语句：

> 我最近开始读《机器学习实战》，现在是在读，整体感觉喜欢，并记下“先完成前三章示例”。

连续核验三个界面：

1. Chat 最终回答准确列出状态、评价和备注；
2. 我的书架出现同一本书，状态和评价一致；
3. 记忆中心出现阅读相关事实，但阅读项的当前状态仍提示在书架管理。

该组截图最能证明“一次语义理解、多业务事实执行”和 Shelf/Memory 协同。若系统返回歧义澄清，应先完成澄清后再截图，不要把失败态当作功能结果。

### S06 版本历史

建议使用无隐私事实：

1. 输入“我有一只三花猫，名字叫小花”；
2. 再输入“把它的名字改为咪咪”；
3. 打开记忆中心，当前事实只能显示“咪咪”；
4. 展开版本时间线，应能回看旧版本“小花”。

该截图应证明 CurrentProjection 只呈现当前值，而 MemoryVersionStore 保留历史；如果当前值仍显示旧名，应先作为缺陷处理，不能写入论文成功案例。

### S07–S08 推荐闭环

准备一个稳定的演示书架，例如包含一本 Python 入门书、一本机器学习实战书和一本不感兴趣的理论书。请求：

> 根据我的书架，为下一阶段推荐 6 本不重复的新书，分别说明适合我当前阶段的原因、实践资源和取舍。

应确认：

- 数量基本满足请求，而不是仅返回 1～2 本；
- 已在 Shelf 的所有状态都不重复出现；
- 推荐理由体现当前 Memory、阅读锚点或反馈，而不是统一模板；
- 精确、易变或外部资源类信息附公共来源；
- 反馈后再次请求时，负反馈候选被抑制或降权。

### S09–S10 Deep Research

选择有多个决策维度、需要比较和外部材料的公开问题。例如“面向已掌握 Python 的本科生设计 3 个月机器学习学习路线，比较教材、在线课程、开源实战项目及适用阶段”。

最终报告应至少包含：执行摘要、目标/约束、分阶段建议、候选比较、风险或取舍、行动路线、局限和来源。研究详情应出现多轮步骤和采纳证据，能够说明下一轮由缺口而不是固定脚本产生。

不要为了截图故意制造 `semantic_plan_unavailable`、`trusted_publication_failed` 或 `book_source_unavailable`。这些是异常路径，不是论文的主要功能成果；如需说明系统鲁棒性，可另做一张附录截图并解释降级策略。

## 6. 脱敏检查表

截图交付前逐张检查：

- [ ] API Key、Bearer Token、Cookie、Authorization Header；
- [ ] 数据库连接串、数据库密码、Redis/搜索服务凭据；
- [ ] 内网域名、局域网 IP、自定义 Provider Base URL；
- [ ] 用户 UUID、thread_id、request_id、receipt_id、source_event_id；
- [ ] 微信二维码、OpenID、头像、真实昵称；
- [ ] 真实姓名、手机号、邮箱、住址、私人宠物/家庭/健康等长期记忆；
- [ ] 模型私有思考过程、原始 prompt、provider_raw、错误堆栈；
- [ ] 研究来源中的付费 Cookie 或带鉴权查询参数。

公共书名、公开网页标题、公共来源 URL、非敏感模型商品名可以保留。若无法确认是否敏感，优先遮挡并在图注中用“演示用户”“公开测试数据”说明。

## 7. 截图与正文配对原则

每个主要功能至少形成一组“真实输入/状态 + 核心代码或流程图 + 真实结果截图”。只截 UI 不解释内部机制，或只贴代码不展示运行结果，都不足以满足第五章要求。推荐将 S03–S05 作为一个完整业务闭环，将 S09–S10 作为一个研究闭环。
